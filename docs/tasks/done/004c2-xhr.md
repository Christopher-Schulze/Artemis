# TASK 004c2: XHR (minimal)

## Why

Older sites and many SDKs still use `XMLHttpRequest` for bootstrap. We provide a minimal implementation that wraps `fetch()` so anything calling `xhr.open / xhr.send` works. WebSocket-client and a true async fetch (parallel HTTP via goroutines + cross-thread Promise resolution) remain deferred.

## Acceptance

- `XMLHttpRequest` global with: `open(method, url, async)`, `setRequestHeader(k, v)`, `send(body)`, `abort()`, `responseText`, `responseType`, `status`, `statusText`, `readyState`, `onreadystatechange`, `onload`, `onerror`, `getAllResponseHeaders()`.
- The implementation is a thin JS-side wrapper over the existing `fetch()` global; therefore it depends on `js.ContextOpts.Fetch` being set (the engine wires it).
- All states transition: 0 (UNSENT) -> 1 (OPENED) -> 4 (DONE). 2 / 3 are skipped (HEADERS_RECEIVED / LOADING) because we don't stream.
- All green.

## Notes

XHR-as-fetch-wrapper means everything is async-style under the hood; even when `xhr.open(...,false)` requests sync, we still resolve via fetch's microtask. The same two-eval pattern applies as for fetch tests.
