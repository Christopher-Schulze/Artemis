# TASK 004 (Phase 3a): DOM mutation surface

## Why

The Phase 2 snapshot bindings make `document.body.innerHTML` readable from JS but not writable, and offer no element mutation methods. After running an inline `<script>` that modifies the DOM, `page.Markdown()` still returns the original content. That breaks the agent path: SPAs and modern websites build their visible content from JS at runtime. Phase 3a closes this gap by replacing the snapshot bridge with a handle-based architecture in which every Go-side `*webapi.Node` is referenced from JS by an integer handle, and JS-side reads and writes always reflect the live Go DOM.

## Acceptance

- `webapi/mutation.go` provides pure-Go DOM mutation helpers operating on `*html.Node`: `SetAttribute`, `RemoveAttribute`, `HasAttribute`, `AppendChild`, `RemoveChild`, `InsertBefore`, `ReplaceChildren`, `SetInnerHTML`, `CreateElement`, `CreateTextNode`, `GetElementById`, `GetElementsByTagName`, `GetElementsByClassName`.
- `js/handle.go` implements a per-context handle table mapping `uint32` IDs to `*webapi.Node`. Identity-stable: passing the same Go node twice returns the same handle.
- `js/dom_bridge.go` rewrites the bridge to expose a small set of native trampoline functions (`__node_get`, `__node_set`, `__node_call`, `__doc_get`, `__doc_call`) plus a JS-side bootstrap script that defines `Element` prototype methods/properties and the `document` object. The bootstrap runs on every `NewContext`.
- After running JS that mutates the DOM, `page.HTML()` and `page.Markdown()` return the mutated content.
- Element JS surface gains: `tagName`, `textContent` (read+write), `innerHTML` (read+write), `outerHTML` (read), `parentNode`, `firstChild`, `nextSibling`, `previousSibling`, `lastChild`, `childNodes` (live array), `setAttribute`, `getAttribute`, `removeAttribute`, `hasAttribute`, `appendChild`, `removeChild`, `cloneNode`, `querySelector`, `querySelectorAll`.
- Document JS surface gains: `getElementById`, `getElementsByTagName`, `getElementsByClassName`, `createElement`, `createTextNode`, plus the existing `title`, `URL`, `body`, `documentElement`, `querySelector`, `querySelectorAll`.
- `make build`, `make vet`, `make test` all green; `go test -race ./js ./engine` clean.
- TASK 003's existing tests continue to pass against the new bridge.

## Notes

The bootstrap JS script lives as a Go string constant in `js/dom_bridge.go`. On `NewContext`, after installing the native trampolines on the global object, we run the bootstrap so that `document`, `Element.prototype`, and helper `__wrap` are available. Trampolines themselves take only primitive arguments so the v8go boundary stays narrow.

`SetInnerHTML` re-parses using `html.ParseFragment(reader, ctx)` where `ctx` is a fresh element node with the same tag as the parent (this is what whatwg specifies). Existing children are detached one-by-one before append, which keeps html.Node parent invariants happy. Detached children remain in the handle table (still reachable from JS that grabbed them earlier) until the context closes; this is web-spec compliant behavior.

Handle table is per-context so closing the context releases everything. There is no per-handle GC; long-lived contexts that churn through nodes will accumulate, but agent-scale workloads (one context per page) handle this fine. A weak-handle scheme can land in a future optimization TASK if it ever shows up on a profile.

`childNodes` returns a fresh array each call - "live" at the call site, not a NodeList object that auto-updates. Spec-strict NodeList auto-update lands when MutationObserver lands.

Reference: research/lightpanda/src/browser/webapi/Node.zig, research/lightpanda/src/browser/webapi/Element.zig, research/lightpanda/src/browser/webapi/Document.zig, research/lightpanda/src/browser/js/bridge.zig.

`nodeType` returns the standard whatwg DOM values (Element=1, Text=3, Comment=8, Document=9, DocumentType=10) rather than the internal `webapi.NodeType` enum, so JS code using `n.nodeType === 1` works as on real browsers.

V8 `RunScript` evaluates each call as a top-level script in the same context. Successive evals that introduce the same `const`/`let` identifier collide ("Identifier ... has already been declared"). Test scripts and any agent-side multi-step JS must wrap in IIFE `(() => { ... })()` or block `{ ... }` to scope locals. Documented in JS section of documentation.md so embedders are not surprised.

`js/dom_bridge.go` was rewritten via Write rather than incremental Edit, because every public function changed signature and the snapshot architecture was replaced wholesale by handle-based trampolines. Surgical edit would have required ~30 separate replacements and risked subtle inconsistencies. Captured here as a documented deviation.
